# Student identity and current branch authority (#61)

Parent #55 stories 6–8, 30, 42–43. Identity access is an additional owner-granted permission and never implies branch reading or profile management. Owner/admin inherit identity authority within their existing center scope. Other staff need both reading and identity in a branch associated with the file; identity writes additionally require profile management in that same branch. Member UI reuses the existing additional-role checkbox and header confirmation. The server enforces every `owner_only` grant, including identity and financial approval.

The tenant migration adds a nullable unique textual Egyptian national number and a nullable textual passport number. Empty values normalize to null; zeros and letters in passports remain intact, passports need not be unique, and a passport without birth date is valid. Existing IDs, primary/manual codes, contacts, creator/timestamps, request hashes and history remain unchanged. Public writes that omit identity preserve its values. Identity data remains in each center's database.

National-number validation checks fourteen ASCII digits, century 2/3, an actual calendar birth date and a nonfuture date. It does not verify the holder, government registration, issuing district or check digit. `POST students/identity-preview` checks current branch and identity-management authority before returning the derived date and conflict with entered/saved dates. No preview changes storage. The shared header offers explicit use of the derived date; save rejects an unresolved birth mismatch rather than silently replacing a saved date. Public birth edits also preserve this consistency, using a generic error that never returns the hidden national number.

Ordinary register/similarity/discovery responses do not select identity values. Detail, authorized save and submission recovery conditionally expose `identity` only within current reading authority. Hidden data is absent, rather than masked values in a public response. Barcode printing contains only the primary internal number. Public audit reports the names of changed identity fields, actor/time/branch and public profile changes; it never stores national/passport values in its details. No national-number search or broader discovery is added.

Writes reuse the center/member lock, current permission read and tenant transaction. Competing creation/update requests cannot bypass national-number uniqueness. Stale changed edits return conflict before domain validation; identical retries add no revision or duplicate event. Replaying an old identity-bearing request cannot bypass a revoked identity grant. No guarantee of atomic changes across separate database connections is introduced.

- Full Laravel suite: 117 tests / 2819 assertions. The final focused run includes the additional century assertion and related profile/numbering/choices/roles/search/suspension suites: 54 tests / 1401 assertions.
- Five real identity browser journeys use production-built Next.js, four Laravel PHP workers, isolated PostgreSQL and real sessions/CSRF. They cover owner creation/edit and retained contact/manual code, concurrent create/update uniqueness, owner grant UI and next-request revocation in an open editor, absent values in unauthorized SSR/API/printing/audit, validation/focus, saved-date conflict, browser Back/cancellation, RTL light/dark and mobile.
- Four existing profile integration journeys pass. The combined profile keeps its passport, barcode, internal number, contact data, sharing and suspension through editing and browser history. Shared-phone warnings and unique native cached-editor submit ownership remain intact.
- The five existing contact journeys and five manual-barcode journeys also pass on the final build: 15 dedicated browser journeys plus the four combined integration journeys.
- Actual SSR members/register/new/profile/edit/search each measure 6 application SQL queries, including server fetches. Intent-prefetched warm navigation retains the header, sends no extra document request and stays within 6. Missing measurements fail acceptance.
- Preview validation initially failed to focus the public birth field because it kept errors inside the identity widget. A failing browser test preceded sharing those errors with the owning form; the invalid birth now receives focus and retains input.
- Lint, TypeScript, production build, Pint and diff checks pass. Desktop light/dark and mobile dark were visually inspected. Derived/saved dates use explicit LTR isolation inside the RTL page.

## Repeatable local acceptance

Use the disposable alpha/beta/staff fixture and proxy described in `docs/student-profile-choices-acceptance.md`, after tenant migrations. From `apps/web`, set `COURSES_IDENTITY_CREDENTIALS` to its absolute mode-0600 credential file and `COURSES_IDENTITY_READ_LOG` to the proxy JSONL log including SSR. Optional `COURSES_IDENTITY_ORIGIN` defaults to `http://alpha.courses.test:8057`. Run `npx playwright test student-identity.spec.ts`; the suite skips without the isolated fixture. All identity values in acceptance are synthetic.
